## 1. 项目定位

个人工作台：一个由自己持续开发、不断往里添加功能的自用系统（笔记、收藏、小工具、AI 能力……）。

**设计目标**

- **加功能成本最低**：新增一个功能 = 增加一个模块目录，不需要改动其他代码
- **单用户、自用优先**：不为假想的多用户需求付出复杂度
- **本地优先**：本机运行，需要时再考虑外网/手机访问

**当前阶段非目标**：多用户 SaaS、微服务、高并发、容器编排。

### 3.3 关键决策记录

- **FastAPI（而非 Django / Flask）**：原生 async；自动生成 OpenAPI 文档（前端类型自动生成的基础）；Pydantic 深度集成。Django 自带 ORM，与 SQLAlchemy 方向冲突。
- **SQLAlchemy 2.1 async（而非同步）**：工作台预计有 AI 调用、外部 API 等 IO 密集场景，async 是顺手组合。**注意：不混用同步/异步会话。**
- **psycopg 3（给 Alembic）+ asyncpg（给应用）**：psycopg 3 的 async 模式**不兼容 Windows 默认事件循环（ProactorEventLoop）**——而 uvicorn 不带 `--reload` 时用的正是它（开发时带 reload 恰好是 Selector，会掩盖这个坑）。asyncpg 两种事件循环都兼容，故应用侧异步用它；Alembic 走 psycopg 的同步模式，不受影响。
- **Vue 3.5（而非 3.6）**：3.6 正式版未发布。发布且生态稳定后升级 —— 官方确认 3.5 → 3.6 无破坏性改动。
- **单用户（非多用户）**：个人自用，数据无需按人隔离。认证以 FastAPI 依赖（`get_current_user`）的形式留好口子，未来要转多用户不用推倒重来。
- **Element Plus**：工作台以表格 / 表单 / 仪表盘为主，它组件最全、中文资料最多，开发速度最快。
- **TypeScript**：长期项目，接口类型由 OpenAPI 自动生成（见 §6），编译期即可发现大量低级错误。
- **pnpm**：快、省磁盘。装在当前 Node 版本下 —— **FlyEnv 切换 Node 版本后需要重装**（`npm i -g pnpm`）。
- **不用 uv、不用 Docker**：Python 版本和本地服务（PG / Redis）交给 FlyEnv，依赖用 venv + requirements.txt。

## 4. 架构：模块化单体 + 功能注册表

这是"工作台能不断加功能"的核心模式：**一个功能 = 一个目录**，加功能不改动既有代码。

### 4.1 目录结构

```
workbench/
├─ docs/                        # 文档（本文在这）
├─ backend/                     # Python 3.14.5 + venv
│  ├─ app/
│  │  ├─ core/                  # 配置 / 数据库会话 / 安全 / 日志 / 异常处理
│  │  ├─ modules/               # ← 一个包 = 一个功能，以后加功能只动这里
│  │  │  └─ notes/
│  │  │     ├─ router.py        # API 路由（薄：只做参数解析和调用 service）
│  │  │     ├─ schemas.py       # Pydantic 入参/出参模型
│  │  │     ├─ models.py        # SQLAlchemy 模型
│  │  │     ├─ service.py       # 业务逻辑（唯一放逻辑的地方）
│  │  │     └─ registry.py      # 功能元信息：名称 / 图标 / 路由 / 描述
│  │  └─ main.py                # 应用入口：自动遍历 modules 挂载路由
│  ├─ alembic/                  # 数据库迁移
│  ├─ tests/
│  ├─ requirements.txt
│  └─ requirements-dev.txt
└─ frontend/                    # Node 24.20.0（FlyEnv）
   ├─ src/
   │  ├─ app/                   # 外壳：布局、侧边导航、首页宫格、路由装配
   │  ├─ features/              # 与后端 modules 一一对应
   │  │  └─ notes/
   │  └─ shared/                # api 客户端、生成的类型、通用组件
   └─ vite.config.ts
```

### 4.2 自动注册（加功能"零改动"的关键）

`app/modules/__init__.py`：

```python
MODULES = ["notes", "bookmarks"]   # 加功能 = 在这里加一个名字
```

`app/main.py`：

```python
from importlib import import_module
from app.modules import MODULES

for name in MODULES:
    router = import_module(f"app.modules.{name}.router").router
    app.include_router(router, prefix=f"/api/v1/{name}", tags=[name])
```

再提供一个聚合接口 `GET /api/v1/modules`，返回各模块 `registry.py` 里的元信息 —— 前端**首页宫格和侧边菜单由它自动生成**，加了新功能首页上自动出现。

### 4.3 API 约定

- 统一前缀：`/api/v1/<模块名>`，例：`/api/v1/notes`、`/api/v1/notes/{id}`
- 错误处理：直接用 FastAPI 原生风格（`HTTPException` + `detail`），前端 axios 拦截器统一处理。**不要自创 `{code, message, data}` 信封。**
- 列表接口分页：`?page=1&size=20`，返回 `{"items": [...], "total": N}`
- 时间：一律 ISO 8601 UTC 字符串（Pydantic 默认行为）

## 5. 数据库约定

- **库名**：`workbench`（单库、`public` schema）
- **表结构全部由 Alembic 迁移管理**；禁止用 `create_all`（测试除外）
- **主键**：`uuidv7`（PG18 原生 `uuidv7()` 函数，时序有序、适合索引、URL 可安全暴露）
- **时间列**：`DateTime(timezone=True)`（PG `timestamptz`），统一存 UTC，展示层转本地
- **命名**：表名复数小写下划线（`notes`）；外键 `<表名单数>_id`（`note_id`）；布尔 `is_xxx`；时间列 `created_at` / `updated_at`
- **软删除**：不做全局约定，个别表需要时自行加 `deleted_at`

模型示例：

```python
import uuid
from datetime import datetime
from sqlalchemy import DateTime, String, Text, Uuid, func
from sqlalchemy.orm import Mapped, mapped_column
from app.core.db import Base

class Note(Base):
    __tablename__ = "notes"

    id: Mapped[uuid.UUID] = mapped_column(Uuid, primary_key=True, server_default=func.uuidv7())
    title: Mapped[str] = mapped_column(String(200))
    content: Mapped[str | None] = mapped_column(Text)
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now(), onupdate=func.now()
    )
```

## 6. 前端约定

- **目录职责**：`app/` 放外壳（布局/导航/路由），`features/<名>` 放具体功能，`shared/` 放跨功能的东西
- **跨边界规则**：feature 之间不互相 import，公共部分一律进 `shared/`
- **类型自动生成**：接口类型**不手写**，执行 `pnpm gen:api-types` 从后端 OpenAPI 生成到 `src/shared/api-types.ts`
- **API 客户端**：`shared/api.ts` 包一层 axios（`baseURL: '/api/v1'`、统一错误拦截、401 处理）
- **状态**：Pinia 只放跨页面状态，页面内状态用 `ref` / `reactive`
- **组件按需引入**：`unplugin-auto-import` + `unplugin-vue-components`（Element Plus 组件按需加载；样式在 `main.ts` 一次性引入全量 CSS，避免 `ElMessage` 这类动态组件的样式缺失）

### 6.1 视觉规范（暖阳主题）

整体走「暖」的调子：**奶油米色打底 + 蜂蜜黄主色 + 暖棕文字**，避免纯白和灰。

- **颜色一律用 CSS 变量，页面里不要写死色值**：
  - 画布/面板：`--warm-canvas`、`--warm-canvas-soft`、`--warm-surface`
  - 主色：`--honey-500`（蜂蜜黄）、`--honey-700`（深主色，用于按钮、白字可读）、`--honey-300`（高亮）
  - 文字：`--ink-900`（标题）、`--ink-700`（正文）、`--ink-500`（次要）、`--ink-400`（更淡）
  - 描边与阴影：`--warm-line`、`--warm-line-soft`、`--warm-shadow-sm/md/lg`（**阴影是暖色**，不是灰）
- 变量定义和 Element Plus 主题覆盖都在 `src/shared/theme.css`：它把 `--el-*` 整套换成了暖色，所以按钮、表格、对话框、分页会自动跟随，**不需要逐个组件改样式**
- 复用类：`.panel`（卡片容器，带圆角+暖阴影）、`.page-head` / `.page-title` / `.page-sub`（页面标题区）
- 新功能的图标：后端 `registry.py` 的 `icon` 填 Element Plus 图标名（如 `Notebook`），前端在 `src/shared/featureIcons.ts` 里登记一下；没登记会退回默认图标

## 8. 编码约定

**后端**

- 用 ruff 做 lint + 格式化（`ruff check --fix` / `ruff format`）
- 分层职责：router 薄（参数解析）、service 厚（业务逻辑）、models / schemas 只做定义
- SQLAlchemy 统一用 2.0+ 写法：`DeclarativeBase`、`Mapped[...]`、`select()`，**不抄旧教程的 `Query` / `declarative_base()`**
- 时间一律 UTC，`timestamptz`
- 日志先用标准库 `logging`（uvicorn 已集成），复杂了再引 loguru

**前端**

- TypeScript 严格模式；接口类型一律来自自动生成，不手写
- 组件文件 PascalCase；feature 内不跨 feature import

**Git**

- 小步提交；`.env`、`.venv/`、`node_modules/` 进 `.gitignore`
- `requirements.txt`、`pnpm-lock.yaml` **必须进版本库**
